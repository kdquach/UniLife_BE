# Use Case Specifications - Canteen Governance & Banner Governance

## Scope

This document defines use cases that are currently implemented across Dashboard FE and Backend API:

- **UC38.1** Review Registration
- **UC38.2** View List Canteens
- **UC40.1** View List Banners
- **UC40.2** View Banner Detail
- **UC40.3** Create Banner
- **UC40.4** Update Banner
- **UC40.5** Delete Banner

| **Description**       | Allows Admin to review a pending canteen registration and set final status.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Preconditions**     | • User is authenticated.<br>• User role is `admin`.<br>• Canteen exists and status is `pending`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Postconditions**    | • Canteen status is updated: `approve -> active`, `reject -> inactive`.<br>• If rejected, related manager accounts are set to `inactive`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Normal Flow**       | 1. Admin opens Canteen Governance page.<br>2. Frontend loads pending canteens via `GET /api/canteens?status=pending`.<br>3. Backend middleware `protect` validates JWT.<br>6. Backend middleware `restrictTo('admin')` validates role.<br>7. Controller validates `decision` value.<br>8. Service checks canteen existence and current `pending` status.<br>9. Service updates canteen status (`approve -> active`, `reject -> inactive`).<br>10. If decision is `reject`, service updates linked manager users to `inactive`.<br>11. Backend returns HTTP 200 with reviewed canteen payload.<br>12. Frontend reloads active and pending lists, then shows success message. |
| **Alternative Flows** | **A. Approve path (Step 3)**<br>A.1 Admin clicks **Approve**.<br>A.2 System sets canteen status to `active`.<br>A.3 Record moves from pending list after reload.<br><br>**B. Reject path (Step 3)**<br>B.1 Admin clicks **Reject**.<br>B.2 System sets canteen status to `inactive` and deactivates linked manager account(s).<br>B.3 Record is removed from pending list after reload.<br><br>**C. Admin does not perform review (Step 3)**<br>C.1 Admin only views list and takes no action.<br>C.2 No review API call is sent.<br>C.3 Data remains unchanged.                                                                                                                                                                                                                                                                                               |
| **Exceptions**        | **E. Invalid decision (Step 7)**<br>E.1 Request body has unsupported decision value.<br>E.2 Backend returns 400.<br>E.3 Frontend shows error message.<br><br>**F. Canteen not found (Step 8)**<br>F.1 Canteen ID does not exist.<br>F.2 Backend returns 404.<br>F.3 Frontend shows error and ends action.<br><br>**G. Canteen is not pending (Step 8)**<br>G.1 Target canteen status is not `pending`.<br>G.2 Backend returns 400.<br>G.3 Frontend keeps current list state.<br><br>**H. Unauthorized/Forbidden (Step 5-6)**<br>H.1 JWT missing/expired/invalid -> 401.<br>H.2 Non-admin user -> 403.<br>H.3 Frontend handles auth/permission error.                                                                                                                                                                                                           |
| **Priority**          | High                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Frequency of Use**  | Frequent                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Business Rules**    | • Only admin can review registration.<br>• Only `pending` canteens are reviewable.<br>• Reject operation has side effect on manager account status.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Other Information** | FE implementation: [UniLife_Dashboard_FE/src/pages/manager/CanteenManagement.jsx](UniLife_Dashboard_FE/src/pages/manager/CanteenManagement.jsx).<br>BE implementation: [UniLife_BE/src/modules/canteen/canteen.routes.js](UniLife_BE/src/modules/canteen/canteen.routes.js), [UniLife_BE/src/modules/canteen/canteen.controller.js](UniLife_BE/src/modules/canteen/canteen.controller.js), [UniLife_BE/src/modules/canteen/canteen.service.js](UniLife_BE/src/modules/canteen/canteen.service.js).                                                                                                                                                                                                                                                                                                                                                             |
